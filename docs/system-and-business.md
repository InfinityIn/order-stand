# Система и бизнес

## Коротко о бизнесе

FreshBox — интернет-магазин доставки продуктов. Заказы приходят с сайта и из
мобильного приложения. Сейчас поток небольшой — около 50 заказов в минуту,
вечером в пятницу бывает втрое больше. К новогоднему сезону планируем 500
заказов в минуту.

Заказ после приёма попадает на склад: комплектовщики работают по списку из
базы данных, курьерская служба забирает собранные коробки дважды в день.
Если заказ не доехал до базы, его никто не соберёт — клиент останется без
продуктов, а мы узнаем об этом из звонка в поддержку через несколько часов.

## Из чего состоит система

```
  браузер / приложение
          |
          v
  [ web ]  -->  [ order-api ]  --(Kafka: топик orders)-->  [ order-worker ]
   nginx          FastAPI                                        |
   :8080          :8000                                          v
                    ^                                      [ postgres ]
                    |                                          :5432
                    +--------------- чтение списка --------------+
```

| Компонент      | Что делает                                                       |
| -------------- | ---------------------------------------------------------------- |
| `web`          | Одна страница: форма создания заказа и список последних заказов.  |
| `order-api`    | Принимает заказ по HTTP, публикует событие в топик Kafka `orders`. Отдаёт список заказов из базы для фронта. |
| `order-worker` | Читает топик `orders`, сохраняет заказы в Postgres.               |
| `postgres`     | Хранилище заказов. Единственный источник правды для склада.       |
| `kafka`        | Брокер сообщений между приёмом и сохранением.                     |

## Формат заказа

Идентификатор заказа генерирует клиент (мобильное приложение или страница
сайта) и присылает вместе с заказом. Приложение повторяет запрос при обрыве
связи, поэтому один и тот же `order_id` может прийти несколько раз.

```json
{
  "order_id": "3f2a9c10-5b7e-4a31-9d44-0c8e1b6f2a77",
  "customer_id": "cust-10423",
  "amount": 2450.00,
  "items": [
    {"sku": "MILK-1L", "qty": 2},
    {"sku": "BREAD-500", "qty": 1}
  ]
}
```

## Требования бизнеса

**Б1. Скорость ответа.** Клиент получает подтверждение приёма заказа не
дольше 200 мс на p95. Замеры маркетинга: каждые лишние 100 мс на этом экране
стоят около процента конверсии.

**Б2. Сохранность.** Ни один принятый заказ не теряется. Если клиент увидел
«заказ принят», заказ обязан оказаться в базе данных.

**Б3. Отсутствие дублей.** Повторная доставка того же сообщения не создаёт
второй заказ. Клиенту нельзя привезти и списать две коробки вместо одной.

**Б4. Задержка обработки.** Заказ появляется в базе не позже 60 секунд после
приёма — иначе комплектовщик уходит на перерыв с неполным списком.

**Б5. Плановые работы.** Перезапуск компонентов, выкатка новой версии и
перезагрузка сервера не приводят к потере или дублированию заказов.

## Что известно об эксплуатации

Дежурства круглосуточные, дежурный — один человек и не автор этого кода. Всё,
что он знает о системе ночью, он узнает из уведомления и из того, что написано
в инструкции к этому уведомлению.

Историй из прошлого две, обе — со слов поддержки, без подтверждения замером:

- В сентябре после планового обновления «часть заказов не доехала до склада»,
  сколько именно — никто не считал.
- В августе один клиент получил две одинаковые коробки и оба раза был за них
  списан.
