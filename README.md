# order-stand

Стенд приёма заказов интернет-магазина: HTTP-приём → Kafka → Postgres, плюс
простой фронт. Репозиторий используется как тестовое задание на позицию
ведущего инженера (DevOps/SRE).

## С чего начать

1. [docs/system-and-business.md](docs/system-and-business.md) — что за система
   и чего от неё хочет бизнес.
2. [docs/task.md](docs/task.md) — что нужно сделать, в какие сроки и по каким
   критериям принимается работа.
3. [docs/acceptance.md](docs/acceptance.md) — порты, запросы к API, команды
   проверки, обязательный минимум.
4. [docs/ai-policy.md](docs/ai-policy.md) — правила работы с ИИ-инструментами.

## Структура

```
src/order-api/       приём заказов, публикация в Kafka, чтение списка из базы
src/order-worker/    чтение топика, сохранение заказов в Postgres
src/web/             одностраничный фронт на nginx
src/db/              схема базы
scripts/load.py      генератор нагрузки, ведёт журнал отправленного
scripts/check.py     сверка журнала с базой: потери и дубли
docs/                описание системы, задание, приёмка, правила по ИИ
```

Файла `docker-compose.yml` в репозитории нет — собрать стенд входит в задание.

## Что нужно на машине

Docker с Compose v2 и примерно 4 ГБ свободной памяти под контейнеры. Порты
8080, 8000, 8001, 5432, 9092 должны быть свободны. Переменные окружения —
образец в `.env.example`.

## Как работать

Ветка от `main`, результат — pull request. Код приложения менять можно и нужно;
`scripts/load.py` и `scripts/check.py` — нельзя.
